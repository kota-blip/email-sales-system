# 請求書集計システム（Google Apps Script版）

Python版（`invoice_system_main.py` 等）と同じ仕様を、**Google Apps Script** で動かすための実装です。
以下の理由から、こちらが推奨構成です。

- GCPサービスアカウントの作成が不要（`SpreadsheetApp`がそのままあなたの権限でSheetsに書き込む）
- Gmail OAuth（`credentials.json`初回ログイン）が不要（`GmailApp`がそのままあなたの受信箱を検索する）
- Heroku等のホスティングが不要（Googleのサーバー上で時間主導型トリガーが定期実行してくれる）
- ネットワーク制限のある環境からでも、Google側で完結するのでTelegramに問題なく届く

必要なのは **Googleアカウント（Gmail・スプレッドシートが使えるもの）** と **Telegram Bot トークン** だけです。

---

## セットアップ手順

### 1. スプレッドシートを新規作成

Google Driveで新しいGoogleスプレッドシートを作成し、名前を「請求書管理」など分かりやすいものにします。

### 2. Apps Scriptプロジェクトを開く

スプレッドシートのメニューから「拡張機能」→「Apps Script」を選択します。
（このスプレッドシートに紐づいた=コンテナバインドのプロジェクトが開きます）

### 3. コードを貼り付ける

デフォルトで `コード.gs` という空のファイルがあります。これを削除し、
このフォルダ（`apps_script/`）にある以下のファイルを、**同じファイル名で**Apps Scriptエディタに作成してコピー＆ペーストしてください。

エディタ左側の「ファイル」の横の「＋」→「スクリプト」で新規ファイルを追加できます（拡張子`.gs`は自動で付きます）。

1. `Config.gs`
2. `SheetsService.gs`
3. `GmailService.gs`
4. `ClaudeService.gs`
5. `Matcher.gs`
6. `TelegramService.gs`
7. `Main.gs`
8. `WebhookHandler.gs`
9. `Triggers.gs`

さらに、エディタ左側の歯車アイコン（プロジェクトの設定）で
「"appsscript.json" マニフェスト ファイルをエディタで表示する」にチェックを入れると
`appsscript.json` を直接編集できるので、このフォルダの `appsscript.json` の内容で置き換えてください
（タイムゾーンをAsia/Tokyoにするための設定です）。

### 4. スクリプト プロパティを設定する

エディタ左側の歯車アイコン「プロジェクトの設定」→ 一番下の「スクリプト プロパティ」→「スクリプト プロパティを追加」で、以下を設定します。

| プロパティ名 | 必須 | 説明 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | ✅ | BotFatherから取得したトークン |
| `TELEGRAM_CHAT_ID` | ✅ | 通知を受け取るchat_id |
| `CLAUDE_API_KEY` | ✅ | Anthropic Claude APIキー |
| `OWN_COMPANY_NAME` | 任意 | 自社名（支払対象アラートの精度向上用） |
| `CLAUDE_MODEL` | 任意 | デフォルト `claude-sonnet-5` |
| `SPREADSHEET_ID` | 任意 | 空でOK（コンテナバインドなら自動でこのシートを使う） |
| `WEB_APP_URL` | 不要 | （旧Webhook方式用。ポーリング方式では使いません） |
| `INVOICE_GMAIL_QUERY` | 任意 | デフォルト `has:attachment filename:pdf newer_than:45d`（キーワード縛りなし。関係ないPDFが多すぎる場合のみ絞り込みを追加） |
| `INVOICE_MATCH_WINDOW_DAYS` | 任意 | デフォルト `60` |
| `INVOICE_MATCH_AMOUNT_TOLERANCE` | 任意 | デフォルト `0.15` |
| `REPORT_AUTO_TRIGGER_DAY` | 任意 | デフォルト `10`（毎月この日ごろに前月分を自動集計） |
| `CONFIRMATION_REMINDER_DAY` | 任意 | デフォルト `15`（未確認ならリマインド） |
| `CONFIRMATION_DEADLINE_DAY` | 任意 | デフォルト `20`（未確認なら期限アラート） |
| `DAILY_CLAUDE_CALL_LIMIT` | 任意 | デフォルト `50`（1日あたりのClaude API呼び出し上限。暴走防止） |
| `MAX_NEW_DOCS_PER_RUN` | 任意 | デフォルト `20`（1回の実行での処理件数上限。暴走防止） |

### 5. 初期セットアップを実行

エディタ上部の関数選択プルダウンで `initialSetup` を選び、▶実行ボタンを押します。

- 初回は「承認が必要です」という権限確認画面が出ます。自分のGoogleアカウントを選び、
  「詳細」→「（プロジェクト名）に移動（安全ではないページ）」→「許可」と進んでください
  （これは自分が書いたスクリプトなので問題ありません。Googleの標準的な確認フローです）
- 実行すると、スプレッドシートに「請求書ログ」「固定支払い先マスタ」「月次サマリ」の3タブが作成され、
  時間主導型トリガー（毎時のGmail監視、毎日9時ごろのスケジュールチェック）が設定されます

### 6. Telegram受信を有効にする（ポーリング方式）

関数選択プルダウンで `switchToPollingMode` を選んで実行します。

これで、1分ごとに Apps Script が Telegram へ新着メッセージを取りに行くトリガーが設定されます。
**ウェブアプリの公開・URL登録・「全員に公開」は一切不要です。**

> 💡 なぜウェブアプリ（Webhook）を使わないのか：
> Google Workspace（法人）アカウントでは、「全員がアクセスできるウェブアプリ」の公開が
> 組織ポリシーで制限され、Telegramからの接続が **302リダイレクト** になって不安定になりがちです。
> ポーリング方式は外部公開が不要なため、この問題を根本的に回避できます。

### 8. 固定支払い先マスタを入力

スプレッドシートの「固定支払い先マスタ」タブに、既存のExcel等から毎月来るはずの取引先を転記します。

| 取引先名 | 頻度 | 概算金額 | 備考 | 有効 |
|---|---|---|---|---|
| 例：〇〇オフィス（家賃） | 毎月 | 300000 | | TRUE |
| 例：△△クラウドサービス | 毎月 | 5000 | | TRUE |

「有効」を`FALSE`にすると、その取引先は漏れ検知の対象から外れます（解約時など）。

### 9. 動作確認

- スプレッドシートを開き直すと、メニューに **「📧 請求書集計」** が追加されています
- メニューから「🔍 今すぐGmailをスキャン」を実行すると、その場でGmailを検索して結果をTelegramに通知します
- Telegramで請求書集計Botに何かメッセージを送ると、コマンド一覧が返ってきます
  （`一覧` / `集計 YYYY-MM` / `スキャン` / `登録 会社名` / `停止` / `再開` / `状態`）

## 運用開始後の動き

- **毎時**：Gmailを自動監視し、新しい請求書/見積書/納品書のPDFを検出したらTelegramに通知（ダブルチェックの起点）
- **毎月`REPORT_AUTO_TRIGGER_DAY`日ごろ**：前月分を自動集計してTelegramに通知
- **毎月`CONFIRMATION_REMINDER_DAY`日ごろ**：まだ未確認ならリマインド
- **毎月`CONFIRMATION_DEADLINE_DAY`日ごろ**：まだ未確認なら期限アラート
- あなたがやることは、Telegramに届く通知に対して **✅承認 / ✏️修正 / ❌却下**、
  月末は **✅確認済みにする** を押すだけです

## 暴走防止（安全装置）

万が一の誤動作でAPI利用料が無駄にかさまないよう、3段階の安全装置を組み込んでいます。

1. **1日あたりのClaude API呼び出し上限**（既定50回/日）：超えると自動的にその日の処理を停止し、
   Telegramに通知します。未処理分は翌日また自動で処理されます
2. **1回の実行あたりの処理件数上限**（既定20件）：何らかの不具合で大量のメールが一致しても、
   1回の実行で使うAPI呼び出しを一定数に抑えます
3. **緊急停止スイッチ**：Telegramで **「停止」** と送ると、Gmail監視・Claude API呼び出しを
   即座にすべて止められます。再開は **「再開」**。今の状態は **「状態」** で確認できます
4. **Telegram Webhookの二重処理防止**：Telegramはウェブアプリの応答が遅い場合、同じメッセージを
   再送してくることがあります。update_id単位で処理済みを記録し、再送分は即座にスキップすることで、
   同じ操作でGmail検索やClaude呼び出しが何度も走ってしまうことを防ぎます

上限に達したときや停止中でも、既にスプレッドシートに記録済みのデータは失われません。

## メールに来ない請求書（郵送・口座引き落とし等）の扱い

Gmail監視の対象外になる支払い（郵送のみの請求書、口座引き落とし、Webポータル払い等）は、
Telegramで **「登録 会社名」** と送ると、メール経由と同じように手動でスプレッドシートに記録できます。

- 金額は入力不要です（後でスプレッドシートに直接記入してください）
- 記録される内容：取引先名・対象月（当月）・支払対象=要払い・ステータス=承認済み
- **「固定支払い先マスタ」にもこの取引先を登録しておくと**、翌月以降もし登録し忘れても
  月末の集計で「未着」として自動的にリマインドしてくれます（既存の漏れ検知の仕組みがそのまま使えます）

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| 初期セットアップで権限エラーが出る | 実行者（自分）のGoogleアカウントでGmail/Sheetsへのアクセスを許可したか確認 |
| Telegramにボタンを押しても反応がない | `switchToPollingMode` を実行し、pollTelegramUpdatesトリガー（毎分）が有効か確認。反応まで最大1分かかります |
| Gmailで検出されない | `INVOICE_GMAIL_QUERY` の条件に合っているか、対象メールがGmailの検索窓で同じクエリでヒットするか確認 |
| Claude APIエラー | `CLAUDE_API_KEY` の設定、APIの利用上限を確認（実行ログに詳細が出ます） |
| 実行ログを見たい | エディタ上部「実行数」タブ、または「表示」→「ログ」 |

## Python版との関係

リポジトリ直下の `invoice_system_main.py` 等（Python/Flask/Heroku版）は、
Herokuなど自前のサーバーで動かしたくなった場合のために残していますが、
今後の運用は基本的に **こちらのApps Script版を主系統** として想定しています。
仕様（Sheetsの3タブ構成、ダブルチェックフロー、支払対象アラート、月次スケジュール）は両者で共通です。
